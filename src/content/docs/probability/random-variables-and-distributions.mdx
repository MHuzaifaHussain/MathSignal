## In everyday terms

<Analogy breaks="The picture breaks if you imagine the card itself being picked by chance, or a face that could win two different amounts: a random variable gives each outcome exactly one number. It also hides that the number has to be a real number. 'Win a red sticker' is a label, not a value you can add up.">

At a school fair there is a die and a prize card. The card says: faces 1, 2 and 3 win nothing, faces 4 and 5 win 1 candy, face 6 wins 5 candies. Before the roll you can't say how many candies you'll take home, only which amounts are possible and how often each one comes up.

The card is the random variable. It doesn't roll anything; it says what each face is worth, before anyone touches the die. Change the card and the game changes, even though the die is the same.

The outcomes don't have to be numbers at all. Draw a playing card and use the rule "a heart wins 1 candy, any other suit wins 0". The two of clubs and the king of spades are different cards, but the rule gives both the number 0. Any rule works, as long as it gives every outcome exactly one number.

</Analogy>

<WhyThisMatters>
Almost every quantity a model predicts or is scored on is a random variable: the class label of the next example, whether the model gets it right (1 or 0), the loss on that example, the next token. Training and evaluation reason about their distributions, not about single outcomes.
</WhyThisMatters>

## A random variable is a rule, not a number

A random variable is a rule that gives every outcome of an experiment one number; the randomness is in which outcome happens, not in the rule. The card doesn't change; what you don't know in advance is the face, and so its number.

### Write the rule as a table

On a small sample space the rule is a table with one row per outcome. The Symbols view writes the game card as X(1) = 0, X(2) = 0, X(3) = 0, X(4) = 1, X(5) = 1 and X(6) = 5: the face goes in, the candies come out. Read X(4) = 1 as "X of face 4 is 1". Deisenroth and coauthors write a two-coin example the same way, one row per outcome, and remark that for a finite sample space the rule is essentially a lookup table (§6.1.2) <Cite id="deisenroth2020" />.

<SideNote>
The name misleads. Deisenroth and coauthors note in a margin of §6.1.2 that a random variable is neither random nor a variable: it is a function <Cite id="deisenroth2020" />.
</SideNote>

<Simpler label="the same card for one coin">

Toss one coin. Let X be 1 for heads and 0 for tails. That is a whole random variable: two outcomes, two rows, one number each. With a fair coin, X is 1 half the time and 0 half the time. This yes-or-no kind of variable, 1 when something happens and 0 when it doesn't, turns up again and again: in the Coins match preset on this page's coin board, and in machine learning.

</Simpler>

### Outcomes that share a value pool their chances

The chance that X equals some number x is the probability of the event made of every outcome the rule sends to x. For the game card, the faces that win 0 candies are 1, 2 and 3, so "X = 0" is the event \{1, 2, 3\} and P(X = 0) = P(\{1, 2, 3\}) = 3/6. The step from one face to three uses additivity from the [probability axioms](/probability/probability-axioms/): the three faces never happen together, so their chances add. This is the board's merge: three tiles land on one bar.

### The distribution: values and their chances

The distribution of a random variable that takes a list of separate values is that list, with each value's probability beside it. For the game card it is 0 with chance 1/2, 1 with chance 1/3, 5 with chance 1/6. Written as a function of the value x, giving P(X = x) for each x, that list is called the probability mass function, and it has to obey two rules: no probability is negative, and the probabilities add up to 1. Goodfellow and coauthors list the same requirements for a probability mass function, and call the second one being normalized (§3.3.1) <Cite id="goodfellow2016prob" />.

Neither rule is an extra assumption. Each P(X = x) is the probability of an event, so it can't be negative. And the events X = 0, X = 1 and X = 5 split the six faces without overlap or gaps, because every face gets exactly one amount, so their chances add up to the chance of the whole sample space, 1. The board shows it every time: "The bars add up to 6/6 = 1."

Once you have the distribution, you answer any question about X by adding bars. The chance of winning at least one candy is P(X = 1) + P(X = 5) = 1/3 + 1/6 = 1/2.

Before you look: let X count the heads in two tosses. X can be 0, 1 or 2. Is P(X = 1) one third?

If one outcome is off, Check names it and the number of heads it should have. When all four match, it says "Yes. X = 1 for HT and TH: 2 of 4 outcomes, so P(X = 1) = 2/4 = 1/2, not 1/3." and the readouts list three bars, with chances 1/4, 1/2 and 1/4 for 0, 1 and 2 heads.

HT and TH are two outcomes with one value, the same lesson as the board on [sample spaces and events](/probability/sample-spaces-and-events/), now drawn as a bar twice as tall as its neighbors.

### Equally likely outcomes, unequal values

Four equally likely outcomes don't make three equally likely head counts. The three values hold different numbers of outcomes, one, two and one, so their chances are 1/4, 1/2 and 1/4. The game card did the same with faces: three faces on 0, two on 1 and one on 5.

Now press Coins match. That preset gives X = 1 when both coins show the same face, HH or TT, and X = 0 otherwise. The readout says "X = 1: HH and TT. 2 of 4 outcomes, so P(X = 1) = 2/4 = 1/2 = 0.50." A random variable that is 1 when an event happens and 0 when it doesn't is called the indicator of that event; this one is the indicator of "the coins match". Yes-or-no variables like this get their own page, together with the [binomial distribution](/probability/binomial-distribution/).

### The distribution forgets which outcomes gave each value

Different rules can have the same distribution. With Coins match still showing, make a new rule, X = 1 when the first coin is heads: press + for HT and − for TT. After the first press the bars read 1/4 and 3/4; after the second they are back where they started, 1/2 and 1/2, but the rule has changed: the two rules disagree on HT and on TT.

So the distribution answers "how likely is each value?", while the rule answers "which outcome gives which value?". For many questions the distribution is all you need. To add two random variables on the same experiment, you need the rules, because you have to know which values happen together.

<CheckYourself level="intuition" question="A rule gives face 1 of a die the value 2 and also the value 3. Is it a random variable?">
No. A random variable gives each outcome exactly one number. A rule that can't decide between 2 and 3 for face 1 is not a function, so it has no single value to put on the chart, and the events "X = 2" and "X = 3" would overlap.
</CheckYourself>

## Notation

<NotationKey symbols={["sample-space", "outcome", "event", "event-collection", "probability", "random-variable", "preimage", "union", "pmf", "sum-over-values", "distributed-as", "indicator", "function-of-random-variable", "cdf", "conditional", "class-label", "feature-vector", "log"]} />

<PreciseStatement>

In plain words: a random variable gives every outcome one real number, and its distribution gives every set of values the probability of the outcomes that land there.

Let $(\Omega, \mathcal{F}, P)$ be a probability space, as on the [probability axioms](/probability/probability-axioms/) page. A (real) random variable is a function $X\colon \Omega \to \mathbb{R}$ such that $\{\omega \in \Omega : X(\omega) \le x\} \in \mathcal{F}$ for every real $x$. On a finite or countable $\Omega$ with $\mathcal{F}$ equal to all subsets, every function qualifies. $X$ is discrete if it takes finitely or countably many values. Its distribution, or law, gives each set $S$ of real values the probability

$$
P(X \in S) = P(\{\omega \in \Omega : X(\omega) \in S\}),
$$

and we write $X \sim P_X$ for "X has the distribution $P_X$". For discrete $X$ the distribution is fixed by the probability mass function $P(X = x)$, which satisfies

$$
P(X = x) \ge 0 \quad \text{and} \quad \sum_{x} P(X = x) = 1,
$$

with the sum over the values $X$ takes, and $P(X \in S) = \sum_{x \in S} P(X = x)$.

Boundary cases and conventions. A number no outcome maps to has probability 0 and gets no bar. A constant $X$ has one value with probability 1, as with All zero on the board. Different random variables can share a distribution. Machine learning texts also call a variable whose states are named categories, with no numerical value, a random variable (§3.2) <Cite id="goodfellow2016prob" />. Sums and other arithmetic need real values, so this page codes labels as numbers when it needs them. The indicator of an event $A$ is $\mathbf{1}_A(\omega) = 1$ if $\omega \in A$ and $0$ otherwise.

</PreciseStatement>

<GoDeeper label="what 'random variable' means on infinite sample spaces" id="random-variable-measurable">

On a finite sample space, every subset can be an event ([sample spaces and events](/probability/sample-spaces-and-events/)), so every rule that gives each outcome one real number is a random variable. On a space such as $[0, 1)$, probability may only be defined on a chosen collection of events, because of [sets no length can measure](/probability/sample-spaces-and-events/#non-measurable-sets). Then a rule has to pass a test: for each real number $a$, the outcomes where the rule's value is below $a$ must form an event, or "the chance that X is below a" would have no meaning. That is Kolmogorov's definition of a random variable (Chapter III, §2) <Cite id="kolmogorov1950" />. In his opening chapter he sums it up: mathematically, random variables are just measurable functions, and their expected values are Lebesgue integrals (Chapter I, §5, p. 8) <Cite id="kolmogorov1950" />. Everything on this page lives on finite spaces, where the test always passes.

</GoDeeper>

<GoDeeper label="a running total of the bars" id="cdf-preview">

Add the bars from the left and you get the cumulative distribution function, $F_X(x) = P(X \le x)$: the chance that X is at most x. For the game card, $F_X(-1) = 0$, $F_X(0) = 1/2$, $F_X(1) = 5/6$, $F_X(2.5) = 5/6$ and $F_X(5) = 1$. It climbs in steps at the values X can take and stays flat in between. Current books, among them Deisenroth and coauthors (Definition 6.2), use "at most", $\le$ <Cite id="deisenroth2020" />. Kolmogorov used "less than": his distribution function is the chance that $x < a$, so it differs from the modern one exactly at the steps (for the card, his value at 1 is 1/2, not 5/6), and he notes that it is continuous from the left (Chapter III, §2) <Cite id="kolmogorov1950" />. The function gets its own page later.

</GoDeeper>

<FormalDefinition>

<StepThrough title="The bars always add up to 1" rigor="full">

1. Let $X$ be a discrete random variable. For two different values $x \ne x'$, the events $\{X = x\}$ and $\{X = x'\}$ share no outcome, because each outcome has exactly one value.
2. Every outcome has some value, so the union of the events $\{X = x\}$ over all values $x$ that $X$ takes is $\Omega$.
3. There are finitely or countably many such events, so additivity (countable additivity when there are infinitely many values) gives $\sum_{x} P(X = x) = P(\Omega) = 1$.
4. Each term is the probability of an event, so $P(X = x) \ge 0$. For the game card: $3/6 + 2/6 + 1/6 = 6/6 = 1$.

</StepThrough>

<StepThrough title="A function of a random variable is a random variable, and its bars merge" rigor="full">

1. Let $X$ be discrete and $g\colon \mathbb{R} \to \mathbb{R}$ any function. Define $Y = g(X)$ as the rule $\omega \mapsto g(X(\omega))$: first apply $X$, then $g$. Each outcome still gets exactly one number.
2. $Y$ takes the value $y$ exactly when $X$ takes some value $x$ with $g(x) = y$, so $\{Y = y\} = \bigcup_{x : g(x) = y} \{X = x\}$, with $x$ running over the values $X$ takes. Likewise $\{Y \le y\} = \bigcup_{x : g(x) \le y} \{X = x\}$ is a union of finitely or countably many events, so it is an event, and $Y$ meets the definition of a random variable.
3. These events are disjoint by step 1 of the previous proof, so additivity (countable additivity when infinitely many values merge) gives $P(Y = y) = \sum_{x : g(x) = y} P(X = x)$.
4. If $g$ gives two values of $X$ the same image, their bars merge into one bar for $Y$; if $g$ is one-to-one, the bars just move. Kolmogorov states the same composition rule for probability functions (Chapter III, §1, equation (2)) <Cite id="kolmogorov1950" />. Worked example 1 below does both cases with numbers.

</StepThrough>

| Property | Statement | On the board |
| --- | --- | --- |
| One value per outcome | each $\omega$ gets exactly one $X(\omega)$ | each face has one stepper value |
| Values split the space | the events $\{X = x\}$ are disjoint and cover $\Omega$ | every tile sits in exactly one bar |
| Never negative | $P(X = x) \ge 0$ | no bar goes below the axis |
| Adds up to 1 | $\sum_x P(X = x) = 1$ | "The bars add up to 6/6 = 1." |
| Sets of values | $P(X \in S) = \sum_{x \in S} P(X = x)$ | at least one candy: $1/3 + 1/6 = 1/2$ |
| Values nobody gets | probability 0, no bar | game card: nothing at 2, 3 or 4 |
| Functions of $X$ | bars move, and merge where $g$ is not one-to-one | $X^2$ merges $-1$ and $1$ (worked example 1) |
| Same distribution, different rule | the law forgets which outcome gave which value | Coins match and "first coin is heads": $1/2$ and $1/2$ |

</FormalDefinition>

## Worked examples

<WorkedExample number={1} title="Shift and square a random variable">

Grinstead and Snell's Exercise 14 in §1.2 (p. 36) gives a random variable $X$ with $P(X = -1) = 1/5$, $P(X = 0) = 1/5$, $P(X = 1) = 2/5$ and $P(X = 2) = 1/5$, and asks for the distributions of $Y = X + 3$ and $Z = X^2$ <Cite id="grinstead2003" />. First check that $X$ has a distribution: $1/5 + 1/5 + 2/5 + 1/5 = 1$.

Adding 3 is one-to-one, so every bar just moves 3 to the right: $Y$ is 2, 3, 4 or 5 with chances $1/5$, $1/5$, $2/5$ and $1/5$. Squaring is not one-to-one, because $(-1)^2 = 1^2 = 1$, so those two bars merge: $P(Z = 0) = 1/5$, $P(Z = 1) = 1/5 + 2/5 = 3/5$ and $P(Z = 4) = 1/5$. Three bars, still adding up to 1.

</WorkedExample>

<WorkedExample number={2} title="Two draws from a bag, not fifty-fifty">

A bag holds red and blue marbles, and a draw gives red with probability $3/10$. Draw one marble, put it back, draw again, and let $X$ count the reds. Putting the marble back means the second draw doesn't depend on the first, so each outcome's chance is a product: about 3 in 10 first draws are red, and of those, about 3 in 10 second draws are red too. The four outcomes are not equally likely, so you add their probabilities instead of counting them:

- $P(X = 2) = 0.3 \times 0.3 = 0.09$,
- $P(X = 1) = 0.3 \times 0.7 + 0.7 \times 0.3 = 0.42$, from red then blue and blue then red,
- $P(X = 0) = 0.7 \times 0.7 = 0.49$.

The total is $0.09 + 0.42 + 0.49 = 1$. The merge is the same as for two coins, two outcomes on one value, but the outcomes bring unequal weights. Deisenroth and coauthors work exactly these numbers with coins from two countries in their Example 6.1 <Cite id="deisenroth2020" />. The board can't show this case, because its dice and coins are fair.

</WorkedExample>

<WorkedExample number={3} title="Count the legs of the predicted animal" faded>

A classifier looks at one image and gives the probabilities cat $1/2$, dog $1/3$ and bird $1/6$, a [softmax output](/probability/probability-axioms/#softmax-outputs). Sample one label from these chances. Let $L$ be the number of legs of the sampled animal (cat 4, dog 4, bird 2) and let $C$ be 1 if the label is cat and 0 otherwise. Given: $P(L = 4) = 1/2 + 1/3 = 5/6$, because cat and dog both give 4. Find $P(L = 2)$ and the distribution of $C$.

<div slot="solution">

Only bird gives 2 legs, so $P(L = 2) = 1/6$, and $5/6 + 1/6 = 1$. $C$ is the indicator of "cat": $P(C = 1) = 1/2$ and $P(C = 0) = 1/3 + 1/6 = 1/2$. The shares $1/2$, $1/3$ and $1/6$ are the game card's: a different experiment with the same chances.

</div>

</WorkedExample>

## Where these rules show up in machine learning

### Labels become numbers by a choice

A classifier's label is a random variable once you code it as a number, and the code is your choice. Goodfellow and coauthors point out that a categorical distribution is over categories, so state 1 is not assumed to have the numerical value 1, and one usually doesn't compute its expected value (§3.9.2) <Cite id="goodfellow2016prob" />. Coding cat, dog and bird as 0, 1 and 2 changes nothing about how likely each label is, but averaging those codes would mean nothing: swap the codes and the "average animal" changes.

Two classes are coded 0 and 1 on purpose, because then arithmetic does mean something: adding the 1s counts the positives. The distribution of such a variable needs a single number, the chance of 1. If that chance is $3/4$, then $P(X = 0) = 1/4$, and one formula covers both cases, $P(X = x) = (3/4)^x (1/4)^{1 - x}$ for $x \in \{0, 1\}$. This is the [Bernoulli distribution](/probability/binomial-distribution/#one-trial-the-bernoulli-distribution), Goodfellow and coauthors' equations (3.16)–(3.18) (§3.9.1) <Cite id="goodfellow2016prob" />. A network with a sigmoid output unit predicts exactly that one number, $P(y = 1 \mid \mathbf{x})$, for each input $\mathbf{x}$ (§6.2.2.2) <Cite id="goodfellow2016" />. Machine learning papers write such random variables in lowercase, the label y here and the noise z and u below; they are random variables just like X. For more than two classes, a softmax output gives the whole distribution at once; the [probability axioms](/probability/probability-axioms/#softmax-outputs) page shows why it always adds up to 1.

### Being right and the loss are rules on outcomes too

Draw one test example at random and run the model on it. "The model is right" is then a random variable: 1 when the prediction equals the label and 0 when it doesn't. The loss on that example is another random variable, a function of the same outcome. With the classifier from worked example 3, if the true label is cat and the model samples its answer from its own probabilities, it is right with chance $1/2$. The usual loss for that example is $-\log$ of the probability the model gave the true class, here $-\log(1/2) = \log 2 \approx 0.6931$.

Test-set accuracy is the share of 1s this variable produces over the test set, as the page on [sample spaces and events](/probability/sample-spaces-and-events/#test-set-accuracy) describes. What that share settles toward in the long run, the [expected value](/probability/expectation-and-variance/), is the next page's subject.

### Generators turn noise into samples

A generative adversarial network is this page's idea at scale: Goodfellow and coauthors' network G maps random noise z to a data point, and so defines the distribution of its samples G(z) without ever writing it down (§§3–4) <Cite id="goodfellow2014" />. The network is the rule, the noise is the outcome, and training shapes the distribution of the samples.

Normalizing flows write the same thing as x = T(u), where u is drawn from a simple base distribution and T is an invertible map (§2.1, equation (1)) <Cite id="papamakarios2019" />. For discrete variables, the survey's equation (99) says that the probability of a value x is the sum of the base probabilities of all u that T sends to x (§5.3) <Cite id="papamakarios2019" />. That sum is the general pushforward rule and works for any map. A flow keeps T invertible, so each x has one u and nothing merges. With a map that is not one-to-one, such as "count the heads" on u uniform over the four coin outcomes, the same rule gives the board's merge: 1/4, 1/2 and 1/4. A limit: GANs and most flows use continuous noise and [densities](/probability/probability-density-functions/).

## Build distributions in code

This runs in your browser with exact fractions and stops with an error if any number on this page is off. Its helper builds a distribution the way the board does: apply the rule to every outcome and add the weights for each value. At the end it simulates the game card and two coins with a fixed seed.

<PyRunner
  title="random_variables.py"
  code={`
import math
import random
from collections import Counter
from fractions import Fraction
from itertools import product


def distribution(outcomes, rule, weights=None):
    """P(X = x) for each value x: add the weights of the outcomes the rule sends to x."""
    if weights is None:
        weights = {outcome: Fraction(1, len(outcomes)) for outcome in outcomes}
    assert sum(weights.values()) == 1, "the outcome weights must add up to 1"
    result = {}
    for outcome in outcomes:
        value = rule(outcome)
        result[value] = result.get(value, Fraction(0)) + weights[outcome]
    return dict(sorted(result.items()))


def is_distribution(chances):

## Research frontier

<ResearchFrontier reviewed="2026-11-25">

**From prize cards to measurable functions.** Kolmogorov made the random variable a function on the sample space: a real single-valued function is a random variable when, for each real $a$, the set where it is below $a$ is an event (Chapter III, §2) <Cite id="kolmogorov1950" />. He defined the probability of its values through pre-images, the sets of outcomes that map into a given set of values (Chapter III, §1, equation (1)), and observed that, mathematically, random variables are measurable functions and their expected values are Lebesgue integrals (Chapter I, §5) <Cite id="kolmogorov1950" />. That settled what a random variable is, on any sample space.

**Generators are random variables you train.** In a generative adversarial network, the generator's samples G(z) have a distribution set by the noise and the network, and Goodfellow and coauthors prove that the global minimum of the virtual training criterion C(G), $-\log 4$, is reached if and only if that distribution equals the data distribution (§4.1, Theorem 1) <Cite id="goodfellow2014" />. Normalizing flows make the map invertible and [differentiable](/calculus/derivatives/) in both directions, which gives an exact density for x = T(u) by a change of variables (§2.1, equations (1)–(2)). The survey shows that, under conditions on the two distributions, such a map exists between any well-behaved target and a simple base (§2.2). For discrete variables, the pushforward is the merge rule on this page, and discrete flows keep it one-to-one (§5.3, equations (98)–(100)) <Cite id="papamakarios2019" />.

**What is open.** Coupling layers are a common building block of flows, and stacking D of them, each splitting the coordinates at the right place, is known to give a universal approximator in D dimensions. The survey says "it is an open problem whether" strictly fewer than O(D) such layers can be (§3.1.2) <Cite id="papamakarios2019" />. Its introduction also points to areas an earlier review labels as open problems, extensions of flows to discrete variables among them <Cite id="papamakarios2019" />.

</ResearchFrontier>

## Check yourself

<CheckYourself level="intuition" question="Five faces of a die win 0 candies and face 6 wins 6. How many bars does the chart have, and how tall is each?">
Two bars: 0 candies with chance $5/6$, because five faces share that amount, and 6 candies with chance $1/6$. The values 1 to 5 get no bar, since no face wins them.
</CheckYourself>

<CheckYourself level="standard" question="A spinner lands on red, green or blue with chances 1/2, 1/4 and 1/4. Red pays 2, green pays 0 and blue pays 2. What is the distribution of the payout?">
$P(\text{payout} = 2) = 1/2 + 1/4 = 3/4$ and $P(\text{payout} = 0) = 1/4$. Red and blue share the payout 2, so their chances add. The outcomes were not equally likely, so you add their probabilities rather than count them.
</CheckYourself>

<CheckYourself level="standard" question="Is P(X = 0) = 0.5, P(X = 1) = 0.4, P(X = 2) = 0.2 a distribution? What about 0.7, 0.5 and −0.2?">
Neither. The first adds up to $1.1$, more than 1. The second adds up to 1 but has a negative chance, $-0.2$. A distribution needs both: every probability at least 0, and a total of exactly 1.
</CheckYourself>

<CheckYourself level="proof" question="Show that if X is a discrete random variable and g is any function, then P(g(X) = y) is the sum of P(X = x) over the values x with g(x) = y.">
The outcome gives $g(X) = y$ exactly when $X$ takes some value $x$ with $g(x) = y$, so the event $\{g(X) = y\}$ is the union of the events $\{X = x\}$ over those $x$. Different values of $X$ never share an outcome, so these events are disjoint, and additivity turns the probability of the union into the sum of their probabilities.
</CheckYourself>

## Common mistakes

<CommonMistakes>
  <Mistake wrong="A random variable is a number that changes randomly.">
    It is a fixed rule that gives each outcome one number; what is random is the outcome. The game card never changes; the face that comes up does.
  </Mistake>
  <Mistake wrong="When the outcomes are equally likely, so are the values.">
    Only if every value holds the same number of outcomes. Count, or add up, the outcomes that give the value: two fair coins give exactly one head with chance $1/2$, not $1/3$, because HT and TH both give 1.
  </Mistake>
  <Mistake wrong="Two random variables with the same distribution are the same random variable.">
    Coins match and "first coin is heads" both give 1 and 0 with chance $1/2$ each, yet they disagree on HT and TT. The distribution forgets which outcome gave which value.
  </Mistake>
  <Mistake wrong="Class labels can be averaged like numbers.">
    Coding cat, dog and bird as 0, 1 and 2 is a choice. The label's distribution doesn't depend on the coding, but an average of the codes does, so it means nothing. Yes-or-no labels are coded 0 and 1 on purpose, so that adding them counts the yeses. The one center a label has is its most common value, the [mode](/statistics/descriptive-statistics/#the-mode-the-most-common-value).
  </Mistake>
</CommonMistakes>
